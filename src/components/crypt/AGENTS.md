# Crypt components

- Privacy sections expand independently and start closed on each opening; keep their contents mounted while collapsed so pending setup keys, drafts and connection checks are not discarded.

- Tips: `/tip` reply adds a direct sender→author CHEESE transfer (fixed memo) to the message transaction, never routed or held by crypt.cheese; tip cards show verified only when that tx has the matching sender-authorized transfer, so cards can't be faked.
- Free sends: build `sendfree` only from an exact [payment, sendmsg] route when a live enabled `budget` row covers the fee; voice/join pass `paid`. History merges `crypt.cheese:sendfree` actions attributed only to the authorizing sender.
- Instant Messaging: a browser key on the `cheesecrypt` permission, linkauth'd only to crypt.cheese::sendfree, signs lone sponsored sendfree actions; everything else stays on Anchor. The key lives only in tab sessionStorage (legacy localStorage copies are purged) and is dropped after 4h without activity, limiting exposure to the open tab. A new key replaces the stored one only after confirmed setup; only auth rejections fall back to Anchor (avoids double sends). Setup prepends a same-account ram.chz buy when free RAM < 1500 bytes. No contract change needed (sendfree only checks require_auth(sender)).
- Padding/ticks/safety: new memos are padded `CRYPT2:` (strip only for that prefix so legacy plaintext ending in 0x80 is untouched; join memos pad to the size leaving room for the carried key). Ticks compare message block time with get_info's last irreversible block time, never per-message lookups; unknown means not permanent. Safety-number verified marks are device-local and keyed to the exact public key so key changes drop them.
- Network privacy: live polls read only the shared crypt.cheese sendfree/sendmsg stream from a cursor (30s overlap, merge by txId:memo), never naming the account; page-cap overflow falls back to a full read. Crypt history reads use cryptHistoryEndpoints (optional device-local custom server first/only). Never add a CHEESEHub-run relay (intermediary liability).
- Device transfer: QR/paste-only (CXFER1 frames, PBKDF2 one-time code → AES-GCM, account+id as AAD); moves only the Anchor-locked envelope and per-account local stores, merging without wiping. Never add WebRTC/cloud sync (server/relay liability) or export plain keys.
- Panic lock: Lock now/double-Esc/Ctrl+Shift+L/idle timer forget the in-memory key and the tab's instant key, then remount Messenger via a page-level nonce so every decrypted cache is discarded by unmounting; the wallet-locked envelope stays so re-unlock is one signature. The tab-switch shield reacts only to document visibility, never window blur (embedded players steal focus).
- Respect (trust score): other accounts' badges show only mark+total, never per-signal holdings (privacy); only the signed-in account's own badge opens the breakdown. Fixed published weights, public chain signals only (no local context) in lib/cryptTrust (pure, tested); badges load public signals only when on screen, cache them in memory, and leave failed reads as unknown (score marked partial, never zero). Never word it as verification and never score on reports (defamation risk); nothing is stored centrally.
- Key rotation: stealth by default (public post opt-in); friends accept rotate notices only when opened with their current key and never revert to previous keys; retired keys are sealed in the locked file under the active secret; room traffic uses the roster-pinned pair and pinned keys are never destroyed.
- Tor helper (public/downloads/cheesecrypt-tor-proxy-v1.6.mjs, filename carries the version): dependency-free, binds 127.0.0.1 only, forwards GET /v2/history + /v2/health and exact signed POST send_transaction/push_transaction bodies, with no traffic files; users run it themselves, never a CHEESEHub-hosted proxy (intermediary liability). On /crypt only, an exclusive loopback setting routes wallet broadcasts through v1.2+, exactly once to one upstream with no direct/alternate retry. A dedicated HTTPS Agent uses SOCKS/Tor-side DNS with certificate checks and no direct fallback; never agent:false (Node ignores its connector). v1.3 adds GET /v2/helper (capabilities), /atomic/v1/assets/<id> and validated /ipfs/<cid> media (image/audio/video types only, 50 MB, in memory, nosniff+sandbox CSP); lib/cryptMediaProxy routes chat NFT metadata/art/audio/video only through a saved loopback helper with those features, fails closed while it is unreachable, and keeps public routing for no helper or a pre-1.3 helper. v1.4 adds read-only POST get_account/get_currency_balance/get_table_rows (JSON object, 16 KB), /atomic/v1/accounts/<name> and /alcor/v2/account/<name>/positions; Respect badges use them only via a v1.4 helper (features chain+respect), stay public for older helpers, and leave lookups unknown and uncached while a saved helper is down (never public fallback). v1.5 (features isolation+rotation) labels every SOCKS stream with username/password for Tor's IsolateSOCKSAuth: one steady history circuit, four cycling media circuits, a fresh circuit per Respect lookup and per broadcast; read-only Respect/NFT/IPFS lookups rotate their starting server, while history stays sticky to one server (indexes differ) and broadcasts stay one-attempt. v1.6 (features prep+atomic-list) adds the remaining read-only chain paths WharfKit uses (get_info, blocks, ABIs, get_required_keys, scopes, currency stats; empty body = {}) and an exact-shape /atomic/v1/assets?owner list; on /crypt, walletRpcFetch sends prep reads only to a v1.6 helper and fails closed while it is down, and the avatar/attach NFT picker lists and draws artwork only through it. Account-named Crypt reads (CHEESE balance, Instant status, /tip balance, sponsor budget, curator/admin table) go through lib/cryptChainRead: v1.4+ helper, public for no/older helper, fail closed while down; the startup balance is skipped on /crypt without a helper. Browser loopback permission and a port-open check do not prove Tor is connected; Fuel/wallet-service traffic and public chain metadata remain outside this protection.

- CryptComposer owns the instant draft; Messenger's text is a transition-deferred mirror, and Send commits the draft urgently before sending so keystroke redraws never block typing or lose text.
- Message rows, quote/edit/inbox previews and the viewport isolate render errors with local retry, without logging plaintext; opaque message identities stay unchanged for receipts and use dataset equality, never dynamic CSS selectors. Reply observers stay attached per mounted active list (reattach after viewport retry) and coalesce visibility work per frame. View-receipt storage failures retain session state; missing/failed rows never consume jump receipts.
- First-run privacy gate: /crypt mounts neither the connect prompt nor Messenger until this device chose public servers or has an exclusive custom server saved, so no account-naming history read happens before the choice; losing the exclusive server re-shows the gate rather than silently using public servers. The setup form's "Use only this server" box is ticked by default and the button only tests the server, reporting success or failure in the panel before anything starts; on success a Continue button opens CHEESECrypt. Unticking the box still saves a first-choice server but records the public choice, since public servers stay reachable.
- Optional send jitter (device-local, off by default, 1–120s whole-second range; master mode off/per-chat/all in Privacy settings, per-chat switches keyed account|chat in each chat's ⋯ Privacy submenu; Instant Messaging only recommended, never required) is a cancellable countdown in CryptComposer before the unchanged send/sendVoice runs, so signed bytes and fees stay identical; leaving the chat or the tab cancels it rather than sending silently in the background.
- Per-message scheduled send (lib/cryptSchedule, up to 24h) reuses the composer's cancellable wall-clock countdown before the unchanged send/sendVoice; edits are never scheduled (24h window), and leaving the chat, the tab or a panic lock cancels it, so nothing is stored or sent unseen. Scheduling requires Instant Messaging to be ready (unattended sends can't wait on Anchor popups); the bypass reads "Skip wait & send now" so it is never mistaken for confirmation.
